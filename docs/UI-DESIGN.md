# PassPlan UI 设计文档

版本 v0.1（草案） · 2026-11-04 · 状态：待评审
配套文档：[DEVELOPMENT.md](./DEVELOPMENT.md)（功能编号 F0 至 F6 对应开发文档 §2）

---

## 1. 设计原则

1. **旅途中单手能用。** 移动优先。主要操作放在拇指能够到的下半屏，点击区域不小于 44×44 px。
2. **结论先行，细节可展开。** 每个页面顶部先给一句话结论（例如"买 7 天 Flexi 省约 €120"），明细折叠在下面。
3. **可信度看得见。** 每个价格、每条规则都标明来源（§5.4 来源标签），用户一眼就知道哪些要自己核实。
4. **规则替用户记。** 规则冲突直接在出问题的那一天、那一段上提示，不让用户自己去对照条款。
5. **AI 是助手，不是主人。** AI 提出改动，用户看清对比后再决定，随时可以撤销。
6. **离线可读。** 行程、订座信息、车次在没网时都能看。需要联网的功能明确标出。

## 2. 视觉方向

**关键词：欧洲站台导向标识 × 纸质通票。**

- **站台导向标识**：深石板色的信息条、高对比的黄色强调、压缩字体的时刻和车次，借用欧洲车站出发信息屏的阅读习惯。
- **纸质通票**：纸质 Interrail 通票封面上有一张 "My Trip" 手写表格，旅客要逐行填写日期和车次。我们的旅行日日历借用这张表格的形式，让老用户一看就懂。火车段卡片做成车票票根的样子，一侧有齿孔分隔线。
- **克制**：只有出发信息条和旅行日标记两处用强烈的颜色，其余界面保持安静，用细线和留白分区，少用阴影。

## 3. 设计令牌

### 3.1 颜色
所有颜色都以 CSS 变量定义在 `app/src/styles/tokens.css`。组件只能引用令牌，不能写死颜色值。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `#F3F5F4` | `#0F1418` | 页面背景（偏冷的纸色，不用米黄） |
| `--surface` | `#FFFFFF` | `#171E24` | 卡片、面板 |
| `--surface-2` | `#E8ECEA` | `#1F2830` | 次级区域、输入框底色 |
| `--line` | `#D2D9D6` | `#2C3740` | 分隔线、边框 |
| `--ink` | `#16202A` | `#E6EBEE` | 主要文字 |
| `--ink-2` | `#4C5864` | `#9AA6B0` | 次要文字、说明 |
| `--board` | `#24303B` | `#0A0F13` | 出发信息条底色（站台屏） |
| `--board-ink` | `#F3F5F4` | `#E6EBEE` | 信息条上的文字 |
| `--signal` | `#F5B700` | `#FFC72C` | 站牌黄：旅行日标记、当前选中、关键数字强调。上面的文字一律用 `--signal-ink` |
| `--signal-ink` | `#1A1400` | `#1A1400` | 黄色上的文字 |
| `--primary` | `#0B6E4F` | `#3FBF8F` | 信号绿：主要按钮、链接 |
| `--primary-ink` | `#FFFFFF` | `#06241A` | 主要按钮上的文字 |
| `--ok` | `#1E7B45` | `#5CCB8A` | 已订、规则通过 |
| `--warn` | `#A35F00` | `#F0A84A` | 建议尽早订、价格不确定 |
| `--danger` | `#B3261E` | `#FF8A80` | 违反规则、必须处理 |
| `--info` | `#1F5FA8` | `#7FB2F0` | 实时数据、提示 |

主题切换：跟随系统（`prefers-color-scheme`），设置中可手动指定浅色或深色（`data-theme` 属性）。
对比度：所有正文与背景的对比度 ≥ 4.5:1，大号文字和图标 ≥ 3:1。上线前用工具逐项检查。

### 3.2 字体
| 角色 | 字体 | 回退 | 用途 |
|---|---|---|---|
| 中文 | Noto Sans SC | PingFang SC, Microsoft YaHei, sans-serif | 全部中文 |
| 拉丁正文 | IBM Plex Sans | system-ui, sans-serif | 英文站名、说明 |
| 时刻与车次 | Barlow Condensed（600） | Arial Narrow, sans-serif | 时间、车次、日期、金额等数字，模仿出发信息屏 |
| 等宽 | IBM Plex Mono | ui-monospace, monospace | 订座号、座位号 |

- **全部字体自托管**，中文字体按常用字子集化并分片加载。Google Fonts 在中国大陆无法访问。
- 数字一律使用等宽数字（`font-variant-numeric: tabular-nums`），保证列对齐。
- 时间统一 24 小时制，例如 `07:42`。日期在界面上显示为 `7月14日 周一`。

### 3.3 字号
| 令牌 | 大小 / 行高 | 用途 |
|---|---|---|
| `--fs-xs` | 12 / 16 | 来源标签、脚注 |
| `--fs-sm` | 14 / 20 | 次要信息 |
| `--fs-md` | 16 / 24 | 正文（移动端最小正文字号） |
| `--fs-lg` | 20 / 28 | 卡片标题 |
| `--fs-xl` | 24 / 32 | 页面标题 |
| `--fs-num` | 32 / 36 | 结论中的关键金额（Barlow Condensed） |

### 3.4 间距、圆角、阴影
- **间距**：4 px 基准，可用值 4 / 8 / 12 / 16 / 24 / 32 / 48。同级元素用 `gap` 控制间距。
- **页面边距**：左右至少 16 px，并考虑手机安全区。
- **圆角**：标签 4 px，卡片和输入框 8 px，药丸形按钮 999 px。不是所有东西都圆角。
- **阴影**：只用于浮层（底部弹出面板、对话框、浮动的 AI 按钮）。卡片用 1 px `--line` 边框区分。

### 3.5 图标
使用一套线性图标库（建议 Lucide），线宽 1.75。火车类型、夜车、换乘、订座等专用图标保持同样风格。不用 emoji 作图标。

## 4. 信息架构与导航

### 4.1 页面结构
```
我的行程（首页）
├── 新建行程（3 步向导）
└── 行程详情
    ├── 路线        F1
    ├── 旅行日      F2
    ├── 订座        F3
    ├── 回本        F4
    └── AI 助手     F5（浮层，可从任意页面打开）
设置              F6
关于 / 隐私说明 / 数据来源
```

### 4.2 网址
| 页面 | 路径 |
|---|---|
| 我的行程 | `/` |
| 新建行程 | `/new` |
| 路线 | `/trip/:id/route` |
| 旅行日 | `/trip/:id/days` |
| 订座 | `/trip/:id/reservations` |
| 回本 | `/trip/:id/value` |
| 设置 | `/settings` |

### 4.3 响应式布局
| 宽度 | 布局 |
|---|---|
| < 600 px（手机） | 顶部栏（返回、行程名、AI 按钮）+ 内容 + 底部 4 个标签：路线 / 旅行日 / 订座 / 回本。AI 助手从底部弹出，占屏幕 90% 高 |
| 600 至 1023 px（平板） | 同手机，内容最大宽度 720 px 居中 |
| ≥ 1024 px（桌面） | 左侧导航栏（240 px）+ 主内容 + 右侧 AI 面板（380 px，可收起） |

### 5.5 来源标签（全局通用组件）
| 标签 | 样式 | 含义 |
|---|---|---|
| `官方` | `--ok` 色描边 | 来自官方网站，带核实日期 |
| `实时` | `--info` 色描边 | 来自 Transitous 实时查询 |
| `你填写` | `--ink` 色描边 | 用户自己输入 |
| `AI估算` | `--ink-2` 色虚线描边 | AI 根据知识估算，未经核实 |
| `AI联网` | `--info` 色虚线描边 | AI 联网搜索得到，附来源链接 |
| `待核实` | `--warn` 色描边 | 数据过期或来源不可靠 |

点击任何标签都会弹出说明：来源网址、核实日期、"报告错误"按钮。

### 5.9 AI 助手
```
┌──────────────────────────────────┐
│ AI 助手 · DeepSeek          ✕     │
├──────────────────────────────────┤
│ 你：第二周太赶了，少去一个城市      │
│                                  │

│ ┌ 改动预览 ───────────────────┐  │
│ │ − 萨尔茨堡（2晚）             │  │
│ │ ~ 慕尼黑  3晚 → 4晚           │  │
│ │ ~ 7天 Flexi → 6天 Flexi      │  │
│ │   费用 €512 → €471  省 €41   │  │
│ │ [ 应用改动 ]   [ 不要 ]       │  │
│ └─────────────────────────────┘  │
│                                  │
│ 你：法国最近有罢工吗？              │
│ AI：…  来源：sncf.com ↗ 2条        │
├──────────────────────────────────┤
│ 常用：[帮我排路线][检查问题][省钱]  │
│ ┌──────────────────────────┐ ➤  │
│ │ 输入问题或要求…            │    │
│ └──────────────────────────┘    │
└──────────────────────────────────┘
```
- **改动预览**：删除用 `−` 和删除线，新增用 `+`，修改用 `~` 并显示前后值。费用变化由规则引擎计算，不用 AI 的数字。
- 应用后顶部出现提示条："已应用 3 项改动 · 撤销"，10 秒后消失；撤销也可在行程菜单中找到。
- AI 回答流式显示。等待时显示"思考中…"和"停止"按钮。
- 联网回答底部列出来源链接。
- 没有 key 时，面板显示设置引导，不显示输入框。

  □ 用密码加密保存 key

外观      跟随系统 / 浅色 / 深色
货币参考  [ 无 ▾ ]（可附加显示人民币、英镑）

## 7. 状态设计

| 状态 | 设计 |
|---|---|
| 首次使用 | 预置示例行程（标注"示例"）+ 首页"新建行程"按钮 |
| 空行程 | 路线页显示"先添加第一个城市"和添加按钮，或"让 AI 帮你排"（有 key 时） |

| 数据过期 | 来源标签显示为 `待核实`，提示"这条信息超过 6 个月未核实" |

## 8. 动效
- 只在三个地方使用动效：底部面板弹出（200 ms）、拖拽排序（跟手）、AI 改动应用后改动项的短暂高亮（600 ms 渐隐）。
- 用户开启"减少动态效果"（`prefers-reduced-motion`）时全部改为直接切换。

## 9. 无障碍
- 所有可操作元素都有清晰的键盘焦点样式（2 px `--primary` 外框）。
- 拖拽排序提供按钮替代方式。
- 颜色不作为唯一的信息载体：通票 / 买票 / 违规同时用文字或图标表示。
- 图标按钮都有 `aria-label`。
- 动态更新（费用重算、AI 回答）使用 `aria-live` 区域播报。
- 目标：WCAG 2.2 AA。

## 10. 文案规范
- **称呼**：用"你"。
- **按钮**：动词开头，说清楚会发生什么。"应用改动"，不写"确定"；"标记为已订"，不写"提交"。
- **错误提示**：说明出了什么问题和怎么解决，不道歉，不含糊。例："Transitous 暂时无法访问。你可以稍后重试，或者手动填写车次。"
- **数字**：金额写成 `€381`；区间写成 `€60–130`；时间写成 `07:42`；时长写成 `4小时16分`。
- **术语表**（全产品统一）：

| 用词 | 不要用 |
|---|---|
| 通票 | Pass、火车通票卡 |
| 旅行日 | 乘车日、使用日 |
| 订座 | 预约、占座 |
| 单独买票 | 点对点票、普通票（"点对点"只在帮助说明里解释时使用） |
| 夜车 | 卧铺车、过夜火车 |
| 欧洲居民 / 非欧洲居民 | 欧盟公民、外国人 |
| 出境行程 / 入境行程 | Outbound / Inbound |

- **站名**：中文名在前，当地名称在后，例如"慕尼黑中央站 München Hbf"。没有通用中文译名的只写当地名称。

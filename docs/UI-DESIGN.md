## 1. 设计原则

1. **手机优先，页面要短。** 主要页面在手机上不超过 2 屏。详细信息点开再看，不要全部铺开。
2. **单手能用。** 主要操作放在屏幕下半部分，点击区域不小于 44×44 px。
3. **结论先行。** 每个页面先给一句话结论，比如"7天 Flexi · 省 €108"，明细放在后面或折叠起来。
4. **可信度看得见。** 每个价格和规则都标明来源（§6.3 来源标签）。
5. **规则替用户记。** 规则冲突直接标在出问题的那一天、那一段上。
6. **AI 是助手。** AI 提出改动，用户看了对比再决定，随时可以撤销。
7. **离线可读。** 行程、订座、车次在没网时都能看。
8. **英文优先，支持多语言。** 所有文案走 i18n。布局按英文长度设计（英文通常比中文长），中文放进去也不会挤。

## 2. 视觉方向

**关键词：年轻、轻快、有旅行感。** 两个贯穿全产品的视觉元素：

- **钱包式通票卡**：通票做成手机钱包里的交通卡，薄荷渐变底，上面是大号的省钱金额和旅行日圆点。完整的卡片只出现在"回本"页，其他页面用缩小的"通票条"（§6.1）。
- **地铁线路图**：路线画成地铁线，每个国家一种线路色，城市是车站。车次标签也用同样的国家色，让人一眼看出这段车在哪个国家。

其他风格要点：大圆角、柔和阴影、毛玻璃顶栏和悬浮的胶囊形底部标签栏、粗体的英文展示字体。

### 3.2 字体
| 角色 | 字体 | 用途 |
|---|---|---|
| 展示 | Bricolage Grotesque（700、800） | 页面标题、城市名、金额、时间、车次 |
| 正文（拉丁） | DM Sans（400、500、700） | 英文和数字正文 |
| 正文（中文） | Noto Sans SC（400、500、700） | 只在中文界面加载 |
| 等宽 | DM Mono（500） | 订座号、座位号 |

- 字体栈：`"DM Sans", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。
- **全部字体自托管**。英文界面不加载中文字体；中文界面再按常用字子集化分片加载。
- 数字列使用等宽数字（`tabular-nums`）。时间统一 24 小时制。
- 英文展示字体字距 `-0.02em`。

### 3.3 字号
| 用途 | 大小 |
|---|---|
| 首页大标题 | 32 px / 800 |
| 页面区块标题 | 19 px / 800 |
| 城市名 | 20 px / 800 |
| 车次时间 | 19 px / 800 |
| 正文 | 15 至 16 px（输入框必须 16 px，避免 iOS 自动放大） |
| 辅助文字 | 12 至 14 px |
| 通票卡金额 | 50 px / 800 |

### 3.4 圆角、阴影、间距
- **圆角**：卡片 22 px，小卡片和输入框 14 至 16 px，按钮、标签、开关 999 px（胶囊形）。
- **阴影**：卡片用柔和阴影 `0 1px 2px rgba(16,24,40,.04), 0 6px 22px rgba(16,24,40,.06)`。浮层（底部标签栏、弹出面板、提示条）用更深的阴影。深色模式阴影加深。
- **间距**：4 px 基准。页面左右至少 16 px，并考虑手机安全区。卡片之间 12 px。

### 3.5 图标：Phosphor
- 默认用 **Bold** 字重。
- **选中状态用 Fill**（底部标签栏、侧边导航）。
- 提示框和功能介绍里的图标用 **Duotone**。
- 按需把用到的图标打包进代码，不加载整套图标字体。
- 许可证：MIT。

### 3.6 标志
- 方案：**站点 P（1a 精修版）**。字母 P 画成一段线路，P 的弯角处是一个车站，柠檬黄圆点带着两个残影从右上角跳出去。
- 两种形态：
  - **完整版**（带残影）：48 px 以上使用。
  - **简化版**（无残影、圆点加大）：32 px 及以下使用，包括浏览器标签图标。
- 颜色用法：

| 背景 | 线路 | 圆点 |
|---|---|---|
| App 图标（薄荷绿方块） | 白色 | 柠檬黄 |
| 白底或浅色底 | 墨色 `#0F1524` | 薄荷绿（柠檬黄在白底上看不清） |
| 深色底 | 白色 | 柠檬黄 |

- 文件在 [`design/logo/`](../design/logo/)：SVG 源文件、16 到 512 px 的 PNG、`favicon.ico`、README 头图（英文）。
- 字标：`passhopper` 全小写，Bricolage Grotesque 800，单独使用。
- 标语：**Plan your Interrail trip. Make the pass pay off.**
- 中文名"通票漫游"只在中文界面和中文推广材料里出现，放在字标下方。

| 宽度 | 布局 |
|---|---|

### 5.2 新建行程（3 步向导）
1. **先认识一下你**：居住地（欧洲 / 欧洲以外，选欧洲时选国家）、年龄段、舱等、人数。
2. **想去哪里**：一句话描述让 AI 生成，或手动添加城市。没有 API key 时显示去设置的引导。
3. **什么时候出发**：出发日期。

顶部有薄荷色进度条和"第 N 步 / 共 3 步"。

- 火车段卡片两行：第一行车次、时间、时长；第二行标签（旅行日或买票、订座、出境入境）和价格区间。点击打开详情面板（§5.4）。
- 调整城市顺序的箭头和"添加城市"只在点"编辑"后出现。

### 5.4 火车段详情（底部弹出面板）
- 标题：路线、日期、起止车站。
- "查时刻表 / 手动填写"切换。候选车次列表旁边显示 Transitous 来源链接（数据条款要求）。
- "去官网核实"一排链接：该国铁路、DB 查询、Seat61。
- 单独买票价格：输入框 +"用这个价格"，以及"AI 估算""AI 联网查"。

### 5.5 旅行日
```
┌──────────────────────────────────┐
│ [通票条：7天 Flexi 省 €108 · 有效期] │
│ ● 用旅行日  ○ 单独买票  拨开关切换    │
│ ┌──────────────────────────────┐ │
│ │[7/14]柏林→慕尼黑    [🔒 买票]  │ │
│ │ 周三 居住国内不出境，只能买票 €60 │ │
│ │[7/16]慕尼黑→苏黎世  [通票|买票] │ │  ← 用旅行日的日期块变成柠檬黄
│ │ 周五 省 €80（票价 €80）· 出境   │ │
│ │ …                              │ │
│ └──────────────────────────────┘ │
│ ┌ 当前安排总花费 €457  [✓ 已是最省] ┐ │
└──────────────────────────────────┘
```
- 一天一行，放在同一张卡片里。左边日期块，中间路线和原因，右边 iOS 式开关。
- 拨动开关后花费实时重算；违反规则的行变成红色底并写明原因。
- 底部深色总价条；改动过时显示"恢复推荐"。

### 5.6 订座
- 顶部：进度环（已订 / 需订）+"N 段要订座 · €合计"。
- **待处理**：每段一张卡片。第一行车次标签、路线、日期；第二行"抢手"标签（名额紧张的车）、订座类型和费用、来源、去哪订的链接；底部"已订好"和"改为买票"。点"已订好"展开订座号、座位、实际花费三个输入框。
- **已订**、**其他**（不用订座或单独买票的段）：一段一行的简洁列表。

### 5.7 回本
- 顶部完整的钱包式通票卡：通票名称、"省 €108"（进入页面时数字从 0 滚动上来）、旅行日圆点、有效期。
- 一条提示：在最便宜的特价票价格下结论会不会反转。
- **方案对比横向条形图**：每个方案一行，条长表示按常见票价算的总花费，浅灰细条表示从最便宜到最贵的区间。推荐方案用主色，"全部买票"用墨色半透明。点击其他方案可以切换。坐标轴从 €0 开始。
- 明细：通票价、订座费（可展开到每段）、单独买票（可展开）、合计。

### 5.8 AI 助手
- 顶部：主色圆形图标 + "AI 助手 · 服务商名"。
- 空状态：大标题"想怎么改你的行程？"和三条能力说明（双色图标）。
- 我的消息：主色气泡。AI 回复：白色卡片。
- **改动预览**：删除用红色圆点"−"并划线，修改用黄色圆点"~"；底部浅绿条显示规则引擎算出的费用变化；"应用改动"和"不要"两个按钮。应用后出现带"撤销"的提示条（10 秒）。
- 底部：一排可横向滑动的常用问题，加胶囊形输入框。

### 5.9 设置
- AI 服务：服务商列表（带品牌色方块）、API key（可显示或隐藏）、模型、测试连接、清除 key、"用密码加密保存"开关，以及"key 只保存在本机浏览器"的说明。
- 外观：跟随系统、浅色、深色。
- 数据：导出、导入、清除全部数据（在页面内二次确认，不用浏览器弹窗）。
- 关于：数据来源、开源地址、免责声明。

### 6.3 来源标签
| 标签 | 样式 | 含义 |
|---|---|---|
| 官方 | 浅绿底绿字 | 来自官方网站，带核实日期 |
| 实时 | 浅蓝底蓝字 | Transitous 实时查询 |
| 你填写 | 灰底墨字 | 用户输入，计算时优先使用 |
| AI估算 | 灰色描边 | AI 估算，未核实 |

## 7. 状态设计
| 状态 | 设计 |

## 8. 动效
只用在这些地方，开启"减少动态效果"时全部关闭：
- 底部面板和 AI 面板从下方弹出（240 ms）
- 旅行日开关的滑块带一点回弹（220 ms）
- 回本页金额从 0 滚动上来、条形图从左长出来（600 至 700 ms，只在进入页面时）
- 卡片悬停轻微上浮（桌面）
- AI"思考中"的三个跳动小点

## 9. 无障碍
- 键盘焦点有清晰的外框。
- 开关使用 `role="switch"` 和 `aria-checked`；可点击的卡片支持回车和空格。
- 颜色不是唯一的信息载体：旅行日、规则冲突都同时有文字或图标。
- 图标按钮都有 `aria-label`；动态更新用 `aria-live` 播报。
- 目标：WCAG 2.2 AA。

## 10. 文案规范

### 10.1 英文（第一版）
- **语气**：友好、直接、像一个懂行的朋友。不用营销腔，不用感叹号。
- **大小写**：按钮和标题用 sentence case（只有首字母大写），例如 "Apply changes"、"Travel days"。
- **按钮**说清楚会发生什么："Apply changes"、"Mark as booked"、"Buy a ticket instead"，不写 "OK"、"Submit"。
- **错误提示**说明问题和解决办法，不道歉。例："Transitous isn't responding. Try again in a minute, or add the train manually."
- **数字和日期**按用户的语言区域格式化。默认 `€381`、`€60–130`、`07:42`、`Wed, Jul 14`、时长 `4h 01m`。
- **术语表**（全产品统一，中文版对应用词同时列出）：

| English | 中文 | 不要用 |
|---|---|---|
| pass | 通票 | rail card、ticket（指通票时） |
| travel day | 旅行日 | ride day、usage day |
| seat reservation / reserve | 订座 | booking（指订座时）、seat ticket |
| buy a ticket / point-to-point ticket | 单独买票 / 买票 | regular ticket |
| night train | 夜车 | sleeper train（统称时） |
| European resident / non-European resident | 欧洲居民 / 非欧洲居民 | EU citizen、foreigner |
| outbound / inbound journey | 出境 / 入境 | — |
| make the pass pay off / worth it | 回本 | — |

- **站名**：英文界面用当地名称（München Hbf）；中文界面中文名在前、当地名在后。

### 10.2 简体中文（第二语言）
- 称呼用"你"，语气轻松但不卖萌。
- 卡片上可以用简写："买票""旅行日"；详情里用完整说法。
- 数字格式：`€381`、`7月14日 周三`、`4小时01分`。
